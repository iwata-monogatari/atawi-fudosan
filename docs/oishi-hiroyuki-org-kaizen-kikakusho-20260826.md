# oishi-hiroyuki.org 改善企画書
## 2028年12月末までに、磐田市民1万人に名前を書いてもらうために

- 作成日：2026年8月26日
- 対象サイト：https://oishi-hiroyuki.org/
- 位置づけ：内部検討資料（本文書はサイトに公開しない。main へマージしないこと）
- 前提：公選法順守ルール（出馬・立候補の表明や示唆、投票依頼、寄附募集を書かない）、「政策」という語を使わない、静的サイト運用（KV/D1 書き込み禁止）は本企画でもすべて維持する。

## 1. ゴールの定義

**2028年12月31日までに、磐田市民1万人が自分の意思で「名前を書いた」状態をつくる。**

- 1万人は、磐田市の人口（約16万人・有権者約13万人規模）の有権者の約7〜8%に相当する。
- これは「サイトのアクセスを増やす」目標ではなく、**名簿（名前・町名・連絡先）が1万件ある**という状態目標である。
- サイト単独では達成できない。本企画書は「サイトを、名前を集める活動全体の**受け皿・信頼装置・紹介ツール**に改造する」計画であり、対面活動と一体で運用する。

## 2. 最初に決めるべきこと：「何に名前を書いてもらうのか」

現在のサイトには、名前を書く対象そのものが存在しない。ここが最大の欠落であり、最初の意思決定事項。

### 案の比較

| 案 | 内容 | 強み | 注意点 |
|---|---|---|---|
| A. 「会」への入会（推奨） | 「大石ひろゆきと次の磐田をつくる会」（仮称）を設立し、入会申込＝名前を書く行為とする | 政治活動として一般的な形。名簿の継続利用（会報・案内送付）が目的として明確。会員数として堂々と数えられる | 会の規約・代表・事務局を整える。政治団体としての届出要否を専門家に確認 |
| B. 「こんな磐田にしたい」への賛同人 | 重点テーマ（/policy）への賛同署名を集める | 入会より心理的ハードルが低い | 「賛同」の使い道が曖昧だと二度目の接点につながらない。連絡先の利用目的を明記する必要 |
| C. 個別テーマ署名の積み上げ | 「体育館にエアコンを」等のテーマ別署名を複数走らせ、合算する | 記事群と相性が良く、参加動機が具体的 | 名簿が分散し重複管理が煩雑。合算1万人の対外的説得力はやや弱い |

**推奨：A を主、B・C を入口として併用。** C（テーマ賛同）で入りやすくし、サンクス画面で A（会入会）へ引き上げる二段構え。最終カウントは A+B の実名簿で行う。

### 法務の事前確認（P0・最優先）

- 着手前に、市選管への事前相談と専門家（弁護士・行政書士）チェックを必ず行う。
  - 会の設立・入会募集は一般的な政治活動だが、**選挙運動の事前運動と評価されない表現・運用**（特定選挙への投票依頼と受け取られる文言の排除）を確認する。
  - 政治団体の設立届・収支報告の要否。
  - サイト上の恒久ルール（出馬表明・示唆をしない、「2029年4月」はビジョンの時期としてのみ言及）は入会ページでも厳守する。
- 個人情報保護：取得項目の最小化（氏名・町名・連絡先。連絡先以外は任意項目を検討）、利用目的の明記、プライバシーポリシーページの新設、台帳へのアクセス制限。

## 3. 現状分析（2026年8月時点）

### 強み（すでに持っている信頼資産）
- 記事276本・磐田Q&A90問・暮らしの調べもの100テーマ・テーマ別ガイド8本。ほぼ毎日更新。
- 「磐田の暮らしを実利で助ける」独自ポジション。磐田AI活用構想・書籍『この街、まだ詰んでない。』・47歳の決意など人物コンテンツ。
- AIツアー（無料・30分）・個別学習サポートという**対面接点の入口**をすでに持つ。
- 磐田物語（500ページ超）・ATAWI系サイト・富士ヶ丘サービス（介護・不動産・塾）の現場ネットワークという**サイト外の資産**。

### 決定的に欠けているもの
1. **名前を書く場所がない。** フォームは問い合わせ・AIツアー申込のみ。
2. **中間プールがない。** LINE公式アカウント・メール配信・SNSがなく、「読者」を「知り合い」に育てる階段がない。一度読んだ人と再会できない。
3. **流入が小さい。** 検索クリックは3か月で約50件。「大石浩之」指名検索は3か月で表示30・クリック4。GA4は2026年8月11日に計測開始したばかり。
4. **進捗を測る指標に「名簿数」がない。** 週次レポートはPV系5指標のみ。

### ファネルの現実（なぜ対面が主戦場か）

仮にSEO施策が成功して平均500PV/日に到達しても：

- 市内からの訪問を3割、訪問→名前記入の転換率を0.3〜1%と置くと、**Web直の獲得は月13〜45人**。28か月でも400〜1,300人。
- つまりWeb直だけでは1万人の1〜2割が上限。**残り8割以上は、対面・紙・紹介で集め、サイトはその受け皿と武器になる**——これが本企画の基本認識。

## 4. 基本戦略：サイトの3つの役割

1. **受け皿（Capture）**：どの経路から来た人も、迷わず名前を書ける。全ページから1クリック。紙でも書ける。
2. **信頼装置（Trust）**：「名前を書いても大丈夫な人か」を確かめに来た人が、毎日更新の実利記事・人物・実績で納得して帰る。既存276本はこのためにある。
3. **紹介ツール（Referral）**：書いた人が次の1人を連れてくるための道具（QR付きカード、シェアしやすいページ、進捗メーター）をサイトが供給する。

## 5. 改善施策（優先度順）

### P0：名前を書ける器をつくる（2026年9〜10月）

1. **法務確認**（前述）。器の名称・文言を確定。
2. **賛同・入会ページ `/nakama`（仮）新設**
   - 1枚で完結：①何をめざす会か（「こんな磐田にしたい」の要約・3分で読める）②入会・賛同フォーム ③紙で書きたい人向けPDF（印刷して郵送・持参・イベント回収）④よくある質問（お金はかかるか＝無料、何に使うか、退会方法）。
   - フォーム項目：氏名（必須）・町名（必須・市民判定用）・連絡先（メールまたは電話・必須）・年代（任意）・応援メッセージ（任意）。
   - 送信基盤：現行の外部フォーム送信方式を踏襲しつつ、**送信内容が単一の名簿台帳（スプレッドシート等）に自動集約される構成**へ。サイト自体に書き込み系を持たない原則（KV/D1禁止）は維持。
3. **全ページ導線**
   - ヘッダーに常設CTAボタン（例：「🖊 名前をつらねる」）。
   - 全記事末尾に定型CTAブロック（middleware で一括差し込み可能）：「この記事が役に立ったら、名前で応援してください」。
   - トップのサイドバー（人物ボックス直下）に進捗付きの誘導ボックス。
4. **サンクスページ `/nakama-thanks`**：お礼＋「身近な2人に伝えてください」＋QR付き紹介画像＋LINE友だち追加（P1開設後）。
5. **進捗メーター**：`data/supporters-count.json` を週次で手動更新し、「いま◯◯人／10,000人」を `/nakama` とトップに表示（静的更新・KV不使用。磐田物語の集合知カウントと同じ運用思想）。
6. **プライバシーポリシーページ新設**、フォーム・フッターからリンク。
7. **週次レポートに「名簿数（累計・今週増）」「LINE友だち数」を第1指標として追加。** PVより上に置く。

### P1：中間プールと紹介の仕組み（2026年10月〜2027年3月）

1. **LINE公式アカウント開設**：全記事末尾・サンクスページ・紙物に友だち追加QR。「いきなり名前は書かないが、つながってもいい」層の中間プール。週1回「磐田の暮らし便り」（その週の記事ダイジェスト）を配信し、節目ごとに入会を案内。
2. **紹介カード（紙・QR付き）**：`/nakama?ref=card` などUTM付きURLで経路をGA4計測。名刺サイズでイベント・店舗・訪問先に常備。
3. **マイクロ賛同（案C）**：反響の大きいテーマ（例：体育館エアコン、給食費、補聴器助成）に「この意見に賛同する」ボタン→氏名・町名入力→サンクスで会入会へ引き上げ。
4. **イベントページ `/events` 新設**：AIツアー・講演・座談会の予定と申込を一覧化。イベントは名簿獲得の主力チャネル（申込時＋当日の紙で二重に接点）。
5. **title・OGP最適化**：主要ページのシェア時見え方を整える（すでにP1系改修の運用があるため延長線で）。

### P2：流入の最大化と関係の維持（2027年）

1. **SEO増産の継続**：暮らしの調べもの100→200テーマ、Q&A90→180問。目標は2027年末に**平均1,000PV/日**。既存の「磐田キーワード100ページ企画書」の路線を継続・倍増。
2. **地区別ページ**（磐田の23地区別・暮らし情報＋その地区の調べものリンク集）：地区集会・回覧板文化と連動する着地点。
3. **会員の実感づくり**：月1回の会報PDF（サイトにも掲載できる公開版）、会員数の節目報告記事（1,000人・3,000人…）。書いた人が「動いている」と感じ続ける仕掛け。
4. **既存ネットワークの動員**：磐田物語・ATAWI系サイトからの相互リンク、富士ヶ丘サービスの現場（介護・不動産・塾の利用者家族）への紙案内。※各サイト・事業の性質を壊さない範囲で、案内は控えめに常設。

### P3：ラストスパート（2028年）

1. **現場入力モード**：`/nakama?kiosk=1`（イベント会場のタブレットで連続入力しやすい簡易表示）。紙回収→週次入力の運用も併走。
2. **見える化強化**：1万人メーターのカウントダウン表示（「あと◯◯人」）、地区別の広がりマップ（概数）。
3. **紹介月間**：四半期ごとに「会員が1人連れてくる」キャンペーン（景品なし・呼びかけのみ。公選法上、物品供与はしない）。

### 対面チャネルの規模感（試算）

- イベント：月4回×平均25人参加×記入率50% ≒ **月50人**。2027年以降は地区集会（23地区×年2巡×30人×50%）を上乗せ。

## 8. リスクと対応

| リスク | 対応 |
|---|---|
| 事前運動と評価される表現・運用 | 着手前の選管相談＋専門家チェック。投票依頼・出馬示唆の文言を書かない現行ルールを入会ページにも適用。公開前チェックリストに「/nakama 関連文言」を追加 |
| 個人情報の漏えい・不安 | 取得項目の最小化、台帳アクセスを本人＋事務局限定・2段階認証、紙は施錠保管、削除依頼窓口の明記。サイト自体に個人情報を保存しない（静的原則の維持） |
| 名簿の質（重複・市外・架空） | 町名必須で市内判定、週次で重複・不備をクレンジング。「磐田市民1万人」の定義を市内在住者名簿で担保 |
| 目標未達 | 四半期レビューで先行指標（月次新規・LINE友だち）を点検し、未達ならイベント頻度・紹介施策・広告的手段（合法な範囲の紙媒体）へ再配分 |
| 書き込み系機能の事故（過去のKV事故の教訓） | フォームは外部サービス経由のみ。カウンターは静的JSONの手動更新。サイトに動的書き込みを実装しない |
| 「集めた名前を何に使うのか」という不信 | 利用目的（会報・催しの案内）をフォーム上に明記し、それ以外に使わない。節目ごとに活動報告記事で還元 |

## 9. 体制と概算費用

- 体制：本人＋事務局1名（台帳管理・週次集計・イベント運営補助）。サイト改修は現行のスキル運用（GitHub→Cloudflare Pages）で内製。
- 概算費用（月）：LINE公式 0〜5千円／フォーム・台帳 0円／印刷物（紹介カード・紙フォーム・会報）1〜3万円／会場費 数千円×回数。**サーバー・システムの追加費用はほぼゼロ**で成立する設計。
- 専門家確認（初回のみ）：数万円規模を想定。

### まとめ

1万人は「サイトを良くすれば集まる」数ではない。しかし現状のサイトには**名前を書く場所すら無い**ため、まずP0で器と導線をつくり、次に中間プール（LINE）と紹介の複利を仕込み、SEOで受け皿への流入を太くする。サイトは28か月間、**毎日更新される信頼の証拠**として対面活動を支え、最終的に名簿1万件という状態でゴールする。
